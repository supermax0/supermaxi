# FINORA Smart Workspace — 0.9.0

## النتيجة والحدود

الصفحة الرئيسية مدمجة في FINORA Management Desktop باستخدام React وTypeScript وTanStack Query وZustand وLucide الموجودة بالمشروع. يحتفظ الشريط العلوي بترتيبه وتصميمه، وتفتح الأقسام داخل مدير النوافذ الأصلي. لا توجد قائمة جانبية جديدة أو نوافذ ويب بديلة للأقسام الأصلية.

لا توجد بيانات عرض تجريبية داخل كود الإنتاج؛ بيانات الاختبار محصورة في ملفات الاختبارات و`e2e/finoraStub.ts`. القيم المالية تأتي من محرك التقارير ودفتر العملاء الحاليين. لا تتغير معادلات المحاسبة أو المخزون أو إصدار الفواتير، ولا توجد جداول جديدة لهذه الميزة.

## مصادر البيانات

| الطلب | المصدر المعاد استخدامه |
| --- | --- |
| `GET /api/v1/desktop/workspace/sales` | `reports_service.parse_filters`, `sales_totals`, `previous`, وتعريف المبيعات نفسه في تقرير المبيعات الأصلي |
| `GET /orders/api/counts` | حالات الطلبات وفلاترها وصلاحياتها الأصلية. إذا لم يسمح الخادم بعدّ الحالات الفرعية، تعرض البطاقة إجمالي الطلبات الظاهرة مع توضيح ذلك |
| `GET /inventory/api/products?page_size=1` | إحصاءات المخزون الأصلية؛ لا تُحمّل قائمة المنتجات لحساب العدد |
| `GET /api/v1/desktop/workspace/receivables` | `customers._workspace_query` نفسه المستخدم في شاشة العملاء، شاملاً الأرصدة الافتتاحية والأقساط والتسديدات الجزئية |
| `GET /api/v1/desktop/workspace/shipping` | حالة `ShippingReport.is_executed` المستخدمة في مسودات الكشوف الأصلية |
| `GET /hr/api/notifications` | تنبيهات الموظفين الحالية وصلاحياتها، مع مشاركة الاستعلام مع جرس الإشعارات وإزالة تكرار مفاتيح التنبيه |
| `GET /api/v1/desktop/workspace/activity?before=…` | `ActivityLog` الحالي، 20 حدثاً في الصفحة، مع حماية الفرع والصلاحيات وملكية الموظف |
| `GET /finora-ai/api/desktop/runtime` و`POST /finora-ai/api/desktop/chat` | حواجز المساعد الحالي و`FinoraAIOrchestrator` ومزوده وإعداداته وأدوات القراءة نفسها؛ لا يوجد مزود أو مفتاح جديد |

يبقى `GET /api/v1/desktop/workspace` يعيد `pages: []` للتوافق مع العملاء السابقين؛ لا يعيد إضافة الصفحات المسحوبة.

## الوظائف المرتبطة

- الضغط على المبيعات يفتح تقرير اليوم، وعلى المستحقات يفتح العملاء ذوي الذمم.
- المتابعة تفتح الطلبات الجديدة، المنتجات المنخفضة أو النافدة، مسودات كشوف الشحن، تنبيه الموظف الأصلي بسياقه، أو إعدادات الأوفلاين مباشرة. يظهر العرض المختصر لأول خمسة تنبيهات، والعرض الكامل داخل مساحة قابلة للتمرير.
- الإضافة والتعديل يستخدمان المحررات الأصلية للمنتج والعميل والمصروف والسند. «إضافة طلب» و«بيع جديد» يستخدمان نقطة البيع الأصلية التي تنشئ الفاتورة/الطلب. لا توجد نماذج مكررة.
- سند القبض يبدأ بنوع تحصيل العميل داخل محرر السندات الحالي ويحتفظ بالتحقق وآلية الاعتماد الأصلية.
- حفظ تفضيلات الظهور والترتيب والاختصارات والكثافة والصفحة الافتراضية لكل خادم وشركة ومستخدم؛ آخر الأعمال والجلسة معزولان حسب الفرع أيضاً.
- استعادة الأقسام والسجلات والتبويبات والتواريخ والصفحات المدعومة بعد إعادة فحص صلاحية فتح القسم. يجري التحقق من السجل بواسطة API الأصلي عند فتحه، ويُعالج السجل المحذوف برسالة واضحة.
- اقتراح اختصار محلي بعد تكرار الاستخدام، بخيارات التثبيت أو التأجيل أو إيقاف الاقتراح. لا يتغير ترتيب المستخدم تلقائياً.
- المساعد للقراءة والاستعلام فقط، ويختفي إن كانت الخدمة أو صلاحيتها غير متاحة. لا يعرض ميكروفوناً أو تنفيذ معاملات غير مدعومين.

## الأمان والاسترداد

حواجز الخادم تستخرج الشركة والفرع من الجلسة الموثقة، ولا تقبل تجاوزهما من معاملات الصفحة. ملخصات المال والعميل تتبع حواجز الأقسام الأصلية. سجل النشاط لا يعيد الحمولة الداخلية أو IP أو مسار الطلب أو التفاصيل المالية؛ المستخدم غير المدير يرى نشاطه المسموح فقط.

مفاتيح الاستعلام تشمل سياق الحساب والفرع والصلاحيات، وتُمنع البيانات السابقة من العمل كبديل عند تبديل السياق. تفضيلات التنقل المحلية لا تحتوي بيانات العملاء أو قيم النماذج أو المبالغ أو أوامر مالية؛ النتائج المالية المحفوظة تستخدم قاعدة الأوفلاين المشفّرة الحالية وعزلها الأصلي.

استعادة الجلسة لا تنفذ حفظاً أو قبضاً أو ترحيلاً. استرداد المسودات المالية يظل محكوماً بالآلية الأصلية الخاصة بالقسم؛ هذه الميزة لا تنشئ استرداداً عاماً لجميع الحقول غير المحفوظة. لم يُعَد بناء نظام المسودات أو المزامنة.

## الأداء والتخطيط

تظهر البنية فوراً، وتحمل المصادر بشكل مستقل مع حالات تحميل وفشل وإعادة محاولة. تُحدّث المؤشرات بعد حفظ العمليات، مع تجميع إشارات التحديث المتزامنة. التحديث الدوري هادئ كل دقيقة أثناء عرض الرئيسية، وتوجد مشاركة لاستعلام المخزون وتنبيهات الموظفين مع الإشعارات الحالية. لا توجد مكتبات أو خدمات جديدة.

في القياس المحلي على 5,000 فاتورة إضافية استغرق ملخص المبيعات نحو **224 ms**. بقي عدد أوامر SQL **292 قبل وبعد** زيادة الفواتير، بما يشمل حراسات السكيمة والمصادقة الموجودة بالنظام؛ لا توجد قراءة صف لكل فاتورة. يعيد الملخص أقل من 500 بايت. هذه نتيجة بيئة الاختبار المحلية وليست قياس تحميل على الإنتاج.

ظهرت المؤشرات في اختبار Electron خلال نحو **1.5 ثانية** بعد تسجيل الدخول. فُحصت الأحجام 1366×768، 1440×900، 1600×900، 1920×1080، 2560×1440، 1024×768، 760×600. لا يوجد تمرير أفقي في القياسات، والبطاقات متساوية الارتفاع؛ تتاح مساحة تمرير عمودية عندما يقل ارتفاع النافذة.

## التحقق

نجحت السلسلة الكاملة ذات **447 اختباراً في 74 ملفاً**، ثم فحوص مركزة للتغييرات الأخيرة. نجحت **15 حالة خادم**، مع تجاوز اختبار OpenAI حي واحد لأنه يتطلب موافقة تشغيل صريحة؛ الاختبار الحقيقي للمساعد هنا استخدم المزود المدمج وORM معزولاً. نجح فحص تصميم الرئيسية والتنقل والتخصيص والمساعد داخل Electron؛ تكتمل أدلة الإصدار في `.codex-tmp/workspace-*.log` و`.codex-tmp/workspace-preview/`.

نجحت الاختبارات المركزة الأخيرة: **77 اختباراً** للأقسام المتأثرة، ثم **9 اختبارات** لمساحة العمل تشمل حالة صلاحية «كل الطلبات» دون صلاحيات الحالات الفرعية. اجتازت اختبارات Electron الثلاثة للواجهة والنسخ والاسترداد. طابقت ملفات JavaScript وCSS وملفات Electron وWASM في الحزم الثلاث البناء المختبر، مع الإصدار 0.9.0 نفسه.

اجتازت الواجهة فحص الحزمة الحديثة فعلياً على Electron 44.4.5 x64، والحزمتين القديمتين على Electron 22.3.27 x64 وia32، على جهاز التطوير. أزمنة المؤشرات تحت اختبار الحزم وتصحيح التشغيل كانت قرابة 4.6 و4.3 و7.4 ثانية على الترتيب، وبدون أخطاء `pageerror`. هذه أزمنة اختبار محلي تشمل الدخول والتحميل البارد، وليست وعداً بزمن ثابت لكل جهاز.

ملاحظة QA: أُغلقت نافذة اختبار الحزمة الحديثة مبكراً مرةً عند جمعها بعد اختبار إعادة التشغيل والاسترداد، ثم حجب خطأ تنظيف مجلد مؤقت الخطأ الأصلي. عُدّل اختبار QA لحفظ الخطأ الأصلي والملف المؤقت عند الفشل؛ نجح فحص الرئيسية منفرداً، ونجحت اختبارات النسخ والاسترداد وفحوص محركَي النسخة القديمة. لم يُنسب هذا الإغلاق إلى سبب في كود الإنتاج دون دليل.

فحوص الإصدار تشمل TypeScript للواجهة وElectron وE2E، وESLint والتنسيق، وبناء الواجهة وحزمة الجرد، واختبارات النسخ المشفّر والاسترداد، ومطابقة محتويات حزم Windows للبناء المختبر. اختبارات الوظائف تستخدم بيانات اصطناعية؛ فحص النشر يقرأ حالات API الحقيقية ويقارن ملخص الذمم بمصدره الأصلي، ولا ينفذ معاملة مالية أو يستدعي مزود AI حياً.

لا يمكن ضمان خلو كل النظام من أخطاء لم تشملها الاختبارات. لم يتوفر جهاز فعلي يعمل بـ Windows 7/8؛ يظل اختبار حزمة Electron 22 على نظام التطوير مختلفاً عن اختبار نظام التشغيل القديم نفسه. الشهادة الرسمية لتوقيع برامج Windows لم تتوفر بعد.
