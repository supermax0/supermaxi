# إعادة جدولة أقساط العملاء — 2026-10-11

من ملف العميل، تبويب الأقساط، يفتح زر «جدولة الأقساط وتاريخ التعديل» جدول الخطة المرتبطة بالفاتورة أو الدين المستقل. النافذة بنفس نمط FINORA، بملخص الدين والمدفوع والمتبقي، جدول قابل للتمرير، تذييل حفظ ثابت، شرح `?`، وسجل السبب والموظف والوقت بتوقيت بغداد مع القيم والمواعيد السابقة والجديدة.

## قواعد العملية

- يتغير توزيع مبالغ الأقساط ومواعيدها فقط. أصل الدين ومجموع المدفوع وأرقام الخطة والأقساط والدفعات الأصلية محفوظة. لا إنشاء سند أو قبض أو صرف أو قيد إيراد. القسط المسدد بالكامل لا يتغير، وأي مبلغ جديد لا يقل عن مدفوع القسط.
- يتحقق الخادم من الشركة وصلاحية إدارة العملاء والفرع والفاتورة غير الملغاة أو المرتجعة، واتساق الفاتورة والخطة والأقساط. يجب إرسال جميع الأقساط الحالية دون إضافة أو حذف، وبمجموع يساوي أصل الدين.
- بصمة الجدول تشمل رصيد الفاتورة والخطة ودفعات الأقساط. أي تحصيل أو تعديل أحدث يرفض المسودة القديمة؛ تحميل أحدث جدول يتطلب تأكيد فقد التعديلات غير المحفوظة.
- يقفل الخادم الفاتورة ثم الخطة ثم الأقساط، ويثبت معرّف العملية ومعلومات التعديل والجدول في معاملة واحدة. إعادة نفس الطلب تعيد النتيجة الأصلية؛ استخدام نفس المعرّف لطلب مختلف مرفوض. إعادة النتيجة السابقة تبقى ممكنة بعد إلغاء الفاتورة، مع رفض تعديل جديد.
- إذا ضاع الرد أو وصل رد غير صالح، تقفل حقول النموذج والإغلاق والتحديث، وتعيد المحاولة نفس البيانات والمفتاح. الخطأ المؤكد يحفظ المسودة ويتيح تصحيحها. بعد النجاح تتحدث بيانات العملاء والحسابات والتقارير.

## التحقق

اختبارات Python تستخدم قواعد بيانات معزولة وخدمات الحسابات الحقيقية: إعادة جدولة خطة فاتورة ودين مستقل بعد تحصيل مصرفي، حفظ أرقام الدفعات وحصصها، عكس السند الأصلي بعد الجدولة، عدم تغيير النقد أو المستحقات، إعادة الطلب دون تكرار التاريخ، رفض تغيير مجموع الدين وخفض مبلغ عن المدفوع والقسط المسدد والأرقام المكررة والغريبة والناقصة والتاريخ غير الصحيح، تعارض رصيد أحدث، الصلاحيات والشركة والفرع، إلغاء الفاتورة، وفشل سجل التعديل مع rollback وإعادة نفس المفتاح.

## المتبقي

الدفعة الأصلية أعلاه تخص تحرير الجدول الحالي. أضيف لاحقاً إنشاء جدول لفاتورة غير مسددة بلا حركة دفع سابقة، وتغيير عدد الأقساط غير المرتبطة بدفعات؛ أدلة وحدود المسار في `docs/finora-customer-plan-builder-verification.md`. أضيف سجل التحصيل وطباعة وCSV لكل حركاته؛ `docs/finora-customer-transactions-verification.md`. يبقى إنشاء دين مستقل جديد من Desktop بمصدر موثق، وجدولة مصادر ذات تاريخ دفع سابق، والكشف التاريخي الكامل لأصل الدين والمرتجعات والرصيد المتسلسل، وOffline والتخزين المشفر للمفتاح بعد إعادة التشغيل. سجل الجدولة يعرض آخر 25 تعديلاً مع العدد الكلي؛ مفتاح النموذج ثابت أثناء فتحه فقط.

التغيير والبناء محليان، ولم ينشر endpoint على سيرفر التشغيل أو تعدل بيانات الشركة الفعلية. فحص Python العام السابق بقي 2114 ناجحاً و59 فاشلاً و10 متروكة؛ البوابة المرتبطة بهذه الدفعة لا تعني نجاح تلك المجموعة العامة. باقي مراحل خطة ERP مستمرة.
