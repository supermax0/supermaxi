## 1. نظرة عامة على النظام

نظام **عيادات Finora** وحدة مستقلة داخل المنصة، تعمل كتطبيق ويب أحادي الصفحة (SPA) داخل غلاف `templates/clinics/workspace.html`، مع واجهات JavaScript في `static/clinics/` وواجهة برمجة JSON تحت `/clinics/api/*`.

| العنصر | الموقع |
|--------|--------|
| تهيئة الوحدة | `modules/clinics/__init__.py` → `init_clinics(app)` |
| المسارات الداخلية | `modules/clinics/routes.py` |
| الحجز العام | `modules/clinics/public_routes.py` |
| النماذج | `modules/clinics/models.py` |
| الحماية والصلاحيات | `modules/clinics/guards.py` |
| مخطط قاعدة البيانات | `modules/clinics/schema.py` (إصدار حالي: `clinics-v26-cardiology-clinical-tools`) |
| الغلاف البصري | `templates/clinics/workspace.html` |
| القائمة العلوية | مجموعة «عيادات Finora» في `templates/base.html` |

### متى يظهر النظام؟

- يظهر فقط عندما يكون نوع نشاط المستأجر = **عيادات** (`clinics`).
- بعد تسجيل الدخول يُوجَّه المستخدم إلى `/clinics/`.
- يُقفل التنقل خارج مسارات العيادة تقريباً (مع استثناءات: الموظفون، الإعدادات، الصلاحيات، الموارد البشرية، الملفات الثابتة، تسجيل الخروج).
- قوائم المحاسبة / التجميل / الأنشطة الأخرى تُخفى لهذا النوع من المستأجرين.

  ├── الأطباء              /clinics/doctors

| `clinics_inventory` | المخزون، الموردون (ومشتريات كاحتياطي) |

- مفاتيح ميزات المستأجر في `utils/tenant_feature_flags.py` تطابق المجموعات أعلاه.

### الربط مع الموارد البشرية (HR)

- مستأجرو العيادات يمكنهم استخدام مسارات HR.
- الطبيب يمكن ربطه بموظف عبر `clinic_doctor.employee_id`.
- جداول الدوام الطبية منفصلة عن الحضور HR.
- الإجازات المعتمدة من HR تؤثر على توفر الطبيب للحجز (حسب خطة الدمج في `docs/CLINICS_DOCTOR_HR_MIGRATION_PLAN.md`).

## 4. تدفق العمل اليومي (الارتباطات العملية)

```
الحجز الإلكتروني (/c/<slug>)
        │
        ▼
طلبات الحجز ← التواصل (اعتماد/رفض) ← مواعيد
        │
        ▼
الاستقبال / قائمة الانتظار
  تسجيل وصول → انتظار → إدخال للطبيب
        │
        ▼
إنشاء زيارة → مساحة الطبيب (/clinics/doctor/<visit_id>)
  سريري · وصفة · فاتورة علاج · تحاليل · أشعة · إجراءات · مرفقات
        │
        ▼
إكمال الزيارة → الفواتير والمدفوعات → الصندوق
        │
        ▼
متابعات / تذكيرات واتساب / تسوية أطباء / تقارير
```

### 5.3 المواعيد — `/clinics/appointments`

| البند | التفاصيل |
|-------|----------|
| **الصلاحية** | `clinics_appointments` |
| **ملف الواجهة** | `static/clinics/appointments.js` |
| **API** | `/api/appointments/board` · `/slots` · إنشاء/تعديل/حالة/إعادة جدولة/أولوية/طوارئ |
| **ملاحظة** | `/clinics/calendar` يُعاد توجيهه إلى هذه الصفحة |

**الميزات:**
- عروض: **اليوم** · **الأسبوع** · **الشهر** · **القائمة**.
- مؤشرات الحالات: مؤكد، حضر، ينتظر، عند الطبيب، ملغي، لم يحضر.
- حجز موعد جديد مع التحقق من الأوقات المتاحة حسب جدول الطبيب.
- تغيير الحالة، إعادة الجدولة، أولوية، موعد طوارئ.
- فلترة حسب الطبيب والتاريخ.

**حالات الموعد:**  
`pending` → `confirmed` → `arrived` → `waiting` → `in_consultation` → `completed`  
(+ `cancelled` · `rescheduled` · `no_show`)

**مرتبطة بـ:** الاستقبال، قائمة الانتظار، المرضى، الأطباء، الخدمات، الجداول، التواصل (حجوزات إلكترونية).

## 9. ما ليس جزءاً من نظام العيادات

- **مركز التجميل** (`beauty_center`) منتج منفصل بمواعيده وجلساته.

## 11. خلاصة تنفيذية

نظام عيادات Finora يغطي دورة العيادة الكاملة:

1. **إعداد** الأطباء والجداول والخدمات والغرف.
2. **حجز** من الاستقبال أو من رابط المريض العام.
3. **تشغيل يومي** عبر الاستقبال والطابور وشاشة الانتظار.
4. **عمل سريري** في مساحة الطبيب مع تحاليل وأشعة وإجراءات ووصفات.
5. **تحصيل مالي** عبر الفواتير والصندوق وتسوية الأطباء.
6. **توريد** عبر الموردين والمشتريات والمخزون والصلاحيات.
7. **تواصل** واتساب/شات وتذكيرات ومتابعات.
8. **تقارير** تشغيلية ومالية من مركز واحد.

كل صفحة تعمل داخل غلاف `/clinics` واحد، وتتصل بالباقي عبر واجهات `/clinics/api/*` وروابط تنقل مباشرة ومعاملات استعلام (`patient_id`, `doctor_id`, `visit_id`).
