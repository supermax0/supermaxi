# تقرير المعاينة الطبية — Doctor Workspace

**النظام:** Finora Clinics  
**الشاشة:** المعاينة الطبية (Doctor Consultation Workspace)  
**المرحلة:** Phase 1  
**التاريخ:** 2026-09-05  
**الحالة:** منفّذة على المسار الحالي `/clinics/doctor/<visit_id>`

---

## 1. الملخص التنفيذي

المعاينة الطبية هي **الشاشة السريرية المركزية للطبيب** أثناء الزيارة الحالية. الهدف أن يعمل الطبيب من مكان واحد دون التنقل بين صفحات متعددة:

- المريض الحالي والطابور
- تسجيل الشكوى والفحص والتشخيص
- الوصفة والإجراءات
- طلب التحاليل والأشعة والمتابعة
- ملخص السجل الطبي للمريض
- حفظ مسودة / طباعة وصفة / إنهاء الزيارة

لا توجد مساحة طبيب موازية ولا منطق سريري مكرر. الصفحة **Orchestration UI** فوق نفس الـAPIs والنماذج الحالية (زيارات، وصفات، تحاليل، أشعة، إجراءات، متابعات، فواتير).

## 2. المسارات والصلاحيات

| المسار | الدور |
|--------|--------|
| `/clinics/doctor` | مدخل الطبيب: يحوّل إلى الزيارة المفتوحة الحالية، أو يعرض حالة الانتظار |
| `/clinics/doctor/<visit_id>` | مساحة المعاينة للزيارة المحددة (المسار الكانوني) |
| `GET /clinics/api/doctor/workspace` | بيانات مجمّعة: الطبيب، الزيارة الحالية، المريض التالي، طابور الانتظار |

**الصلاحية الأساسية:** `clinics_clinical`

**القائمة الجانبية:** عنصر «المعاينة الطبية» يظهر لمن لديهم صلاحية سريرية (مخفي عن شخصية الاستقبال كواجهة رئيسية).

## 3. التصميم العام (UI / UX)

### 3.1 فلسفة التصميم

- Modern Clinical Workspace
- كثيف وواضح (Dense but readable)
- خلفية فاتحة بيضاء/رمادي طبي
- لون أساسي Finora Teal (`#0d9488`)
- بطاقات بزوايا 12px تقريباً وظلال خفيفة
- بدون Hero Banner كبير
- RTL كامل

### 3.2 تخطيط الصفحة (Desktop)

على شاشة المعاينة فقط (scoped):

1. **Sidebar النظام** — يسار الشاشة (داكن)
2. **ثلاثة أعمدة للمحتوى:**
   - **يسار:** طابور الطبيب (المريض الحالي / التالي / قائمة الانتظار)
   - **وسط:** مساحة الزيارة (الأكبر)
   - **يمين:** ملف المريض المختصر (السياق الطبي)

```
┌──────────┬─────────────┬──────────────────────┬────────────────┐
│ Sidebar  │ Queue       │ Current Visit        │ Medical        │
│ (داكن)   │ المريض الحالي│ Workspace            │ Context        │
│          │ التالي      │ الشكوى · الفحص · ... │ ملخص · زيارات  │
│          │ الانتظار    │                      │ أدوية · تحاليل │
└──────────┴─────────────┴──────────────────────┴────────────────┘
                           Sticky Footer: مسودة · طباعة · إنهاء
```

### 3.3 Header المضغوط

- عنوان: المعاينة الطبية
- شريط بحث سريع (بحث مريض)
- الوقت الحالي
- حالة: ● مع مريض حالياً / بانتظار
- اسم الطبيب والتخصص
- زر: العودة لقائمة الانتظار

ملاحظة: الـTopbar العام للعيادة يُخفى داخل هذه الصفحة لتقليل الازدحام.

### 3.4 Sticky Footer

## 4. أعمدة الواجهة بالتفصيل

### 4.1 عمود الطابور (Queue Panel)

**المريض الحالي**

- الاسم، رقم الملف، العمر، الجنس، الهاتف
- تنبيه حساسية واضح (نص + لون، وليس لوناً فقط)
- وقت الدخول
- **مدة المعاينة Live** (تحديث كل ~30 ثانية بدون إعادة رسم الصفحة كاملة)
- رقم الزيارة بصيغة `VIS-xxxxx`

**المريض التالي**

- الاسم والملف ووقت الموعد
- مدة الانتظار
- الحالة (وصل / بانتظار الطبيب)
- رابط عرض قائمة الانتظار
- لا يُدخل الطبيب المريض التالي قبل إنهاء الحالي عبر مسار الاستقبال/الطابور

**قائمة انتظار اليوم**

- حتى 8 مرضى بترتيب الأولوية ورقم الطابور
- تحديث دوري عبر `GET /api/doctor/workspace` (~40 ثانية)

### 4.2 عمود الزيارة (Current Visit Workspace)

رأس الزيارة:

- رقم الزيارة
- نوع/اختصاص
- وقت البدء
- حالة: قيد المعاينة / مكتملة
- أزرار سريعة: تحاليل · أشعة · إجراء · متابعة

**التبويبات**

| تبويب | المحتوى |
|-------|---------|
| الزيارة | الشكوى، التاريخ، العلامات، الفحص، التشخيص، المتابعة، المرفقات |
| الفحص | نموذج الاختصاص الديناميكي (إن وُجد template) |
| العلاج | خطة علاج الأسنان (Dentistry) |
| الأطفال / النسائية / الباطنية / القلب | أدوات التخصص حسب كود الاختصاص |
| الوصفة | Prescription Builder + قوالب + طباعة |
| الفاتورة | بنود العلاج، خصم، إجراءات، معاينة طباعة |

**أقسام تبويب الزيارة**

1. الشكوى الرئيسية (textarea)
2. التاريخ المرضي (من السجل / الأمراض المزمنة)
3. العلامات الحيوية (عرض شريطي + تحديث عبر نموذج مخفي حتى الضغط)
4. الفحص السريري
5. التشخيص (متعدد؛ كود اختياري + عنوان)
6. الخطة العلاجية (توجيهية؛ التفاصيل عبر ملاحظات/وصفة/إجراءات)
7. المتابعة (preset أيام أو تاريخ + إنشاء متابعة رسمية)
8. المرفقات (رفع مرتبط بالمريض والزيارة)
9. ملاحظات نهائية

### 4.3 عمود السياق الطبي (Patient Medical Context)

- رأس مع تبويبات واجهة: الملخص · الزيارات · الأدوية · التحاليل · الأشعة
- بطاقة المريض + تنبيه الحساسية
- ملخص سريع: أمراض مزمنة · آخر تحليل · آخر أشعة · عدد التشخيصات
- الزيارات السابقة (فتح Drawer للقراءة فقط دون تغيير سياق الزيارة الحالية)
- الأدوية الحالية من الوصفات النشطة

## 5. سير العمل (Workflow)

```
الاستقبال / الطابور
    │  «إدخال للطبيب»
    ▼
POST /clinics/api/visits { appointment_id }
    │  appointment → in_consultation
    │  visit → open + started_at
    ▼
Redirect → /clinics/doctor/<visit_id>
    │
    ▼
المعاينة (تسجيل سريري + طلبات)
    │
    ├── حفظ مسودة (PUT visit)
    ├── وصفة / تشخيص / علامات / إجراءات / Labs / Rad / Follow-up
    └── إنهاء الزيارة (POST .../complete)
            │
            ▼
        ملخص نجاح داخل الشاشة
            ├── المريض التالي / طابور الطبيب
            ├── الفواتير
            └── قائمة الانتظار
```

**نقطة مهمة:** بعد «إدخال للطبيب» من الاستقبال يتم **deep-link** مباشرة إلى صفحة المعاينة الصحيحة (مثل سلوك الطابور/اللوحة).

**حالة الانتظار:** فتح `/clinics/doctor` بدون زيارة مفتوحة يعرض Waiting State + قائمة الانتظار، وليس خطأ.

## 7. المعمارية التقنية

### 7.1 المبدأ

> لا تكرار للمنطق السريري. الـWorkspace ينسّق واجهة فقط فوق الخدمات الحالية.

### 7.2 الملفات الرئيسية

| الملف | الدور |
|-------|------|
| `modules/clinics/routes.py` | `/doctor`, `/doctor/<id>`, `GET /api/doctor/workspace` |
| `modules/clinics/service_visits_registry.py` | `doctor_workspace()` — تجميع الزيارة الحالية والطابور |
| `static/clinics/doctor.js` | `ClinicsDoctorWorkspace` — واجهة المعاينة |
| `static/clinics/clinics.js` | يفوّض `renderDoctor()` إلى الوحدة الجديدة |
| `static/clinics/clinics.css` | أنماط `.cx-ws*` + تخطيط الصفحة |
| `templates/clinics/workspace.html` | تحميل `doctor.js` + رابط القائمة |
| `static/clinics/reception.js` | deep-link بعد إدخال للطبيب |
| `static/clinics/nav.js` | مفتاح تنقل `doctor` |
| `modules/clinics/service_dashboard.py` | ظهور عنصر القائمة حسب الشخصية/الصلاحية |

### 7.3 APIs المستخدمة (بدون تكرار كتابة)

| العملية | API |
|---------|-----|

| علامات حيوية | `POST .../vitals` |
| تشخيص | `POST .../diagnoses` |
| وصفة | `POST .../prescription` |

## 8. التكامل مع باقي النظام

| النظام | التكامل |
|--------|---------|
| الاستقبال | إدخال للطبيب → إنشاء/فتح زيارة → فتح المعاينة |
| الطابور | نفس انتقال الحالة؛ الطبيب يرى الانتظار داخل الشاشة |
| لوحة الانتظار / Reception Board | تتحدث عبر حالات الموعد/الزيارة الموجودة |
| الفوترة | عند الإنهاء يمر مسار `complete` + invoice الحالي |
| السجل الطبي | السياق الجانبي يقرأ clinical record؛ لا ينسخ البيانات |
| التخصصات | mounts موجودة كما في مساحة الطبيب السابقة |
| Audit | عبر دوال الـservice الحالية عند الإنشاء/التحديث/الإكمال |

## 9. الأمان والخصوصية

- الطبيب المرتبط يرى زيارته/طابوره حسب نطاق الطبيب الحالي في النظام
- الصفحة تتطلب `clinics_clinical`
- المعلومات المالية تظهر فقط إن وُجدت صلاحية `clinics_billing` في مسارات الزيارة
- الاستقبال لا يعتمد هذه الشاشة كواجهة تشغيل يومية
- زيارة سابقة تُفتح للقراءة فقط (Drawer) دون تبديل سياق الزيارة الحالية

## 11. كيفية التجربة السريعة

1. من الاستقبال أو الطابور: اضغط **إدخال للطبيب** على مريض بانتظار.
2. يجب أن تُفتح `/clinics/doctor/<visit_id>` مباشرة.
3. أو افتح من القائمة: **المعاينة الطبية** → `/clinics/doctor`.
4. سجّل شكوى/تشخيص/وصفة، جرّب طلب تحليل أو أشعة من الأزرار السريعة.
5. **حفظ كمسودة** ثم **إنهاء الزيارة** وتحقق من ملخص النجاح وروابط الطابور/الفواتير.

---

## 12. الخلاصة

المعاينة الطبية أصبحت **قلب العمل السريري للطبيب** في Finora Clinics:

**المريض الحالي + الزيارة + التشخيص + العلاج + الوصفة + الطلبات + السجل المختصر + إنهاء الزيارة**  
من شاشة واحدة، فوق البنية الحالية، مع تصميم Clinical Workspace جاهز للتوسعة في Phase 2.
