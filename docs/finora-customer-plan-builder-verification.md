# إنشاء وتقسيم جدول الأقساط — 2026-10-11

تحديث لاحق: توسع إنشاء الجدول إلى فاتورة ذات تحصيل مباشر سابق أو رصيد قديم غير مفصل؛ حدود الحماية وأدلة التحقق الحالية في `finora-customer-prior-payments-verification.md`. قيود «بلا حركة دفع سابقة» ونتائج هذا التقرير تصف دفعة الإنشاء الأولى، وليست الحد الحالي لجميع مصادر التحصيل.

من فاتورة العميل يفتح «إنشاء جدول أقساط» معاينة العدد وأول استحقاق والتكرار والسبب قبل الحفظ. ومن جدول قائم يفتح «تغيير عدد الأقساط المتاحة» نافذة بنفس نمط FINORA. إذا كانت هناك تعديلات غير محفوظة بالجدول الحالي، تُحفظ أو يعاد تحميله أولاً؛ لا تُسقط التعديلات عند الانتقال.

## حدود العملية والمصادر

- إنشاء الجدول يخص فاتورة موجودة غير مسددة، بلا خطة أو حركة دفع سابقة غير صفرية أو تخصيص مالي. الملغاة والمرتجعة والمقفلة للمخزون وفواتير جهة الشحن لا تدخل. إذا للفواتير جدول أو تاريخ دفع، يظهر سبب منع الإنشاء دون الكتابة عليه.
- هذه جدولة لأصل فاتورة موجود، وليست إنشاء بيع أو دين مستقل أو قبض. قيمة الفاتورة ومدفوعها وحركة النقد والمخزون والقيود لا تتغير؛ خطة الفاتورة لا تضيف أصل الدين مرة ثانية.
- تغيير العدد يخص المبلغ في الأقساط غير المرتبطة بدفعات فقط. أي قسط فيه مدفوع أو سجل دفعة، حتى إذا عُكست بالكامل وصار صافي المدفوع صفراً، يبقى برقم السجل وترتيبه ومبلغه وتاريخه. تُستعمل الصفوف المتاحة أو تضاف صفوف جديدة؛ لا يحذف صف مرتبط بدفعة. العدد الكلي يتضمن المحفوظ والمتاح، ولا يتجاوز 240؛ لا يوجد قسط جديد أقل من دينار.
- الشهري يحافظ على يوم أول استحقاق، ويقصر إلى آخر يوم بالشهر عند الحاجة، ثم يعود لليوم الأصلي بالشهر التالي. مثال 31 يناير → 28 فبراير → 31 مارس. الأسبوعي كل سبعة أيام. الفارق العددي يضاف للقسط الأخير، دون تقريب عائم.
- الشركة والفرع والمستخدم النشط وصلاحية إدارة العملاء تتحقق في المعاينة والحفظ. بصمة المصدر تشمل الرصيد والجدول وروابط الدفعات، فتكتشف أيضاً دفعة وعكسها مع بقاء صافي المدفوع نفسه.
- معرّف الطلب وبصمته وسجل قبل/بعد والجدول تحفظ بمعاملة واحدة. قيد فريد مستقل لمصدر الفاتورة يمنع إنشاء خطة ثانية بمعرّف طلب آخر؛ التراجع يحذف القيد والجدول والإيصال معاً. لا يجوز إعادة استعمال المعرّف ببيانات مختلفة أو مستخدم/فرع آخر.
- عند رد شبكة أو خادم أو استجابة غير صالحة، تقفل حقول وإغلاق النموذج، وتكرر نفس البيانات والمفتاح. تعارض مؤكد يحفظ المسودة ويتيح تحميل أحدث مصدر بتأكيد صريح. هذا التعافي أثناء فتح النموذج؛ لا توجد هنا ذاكرة مشفرة لمفتاحه بعد إعادة تشغيل التطبيق.
- سجل التعديل يوضح الصفوف المضافة والمحذوفة غير المرتبطة بدفعات. عند إعادة استخدام رقم خطة محذوفة في SQLite، لا تُنسب سجلات تعديلها السابقة إلى الخطة المنشأة حديثاً؛ سجل الخطة يقيد بتاريخ إنشائها.
