# جدولة فواتير ذات سندات تحصيل سابقة — 2026-10-11

يمكن إنشاء جدول للمتبقي من فاتورة لها سند تحصيل أو تسوية رصيد عميل قبل إنشاء الجدول. تعرض المعاينة أرقام السندات وتواريخها وحصة الفاتورة وحالة العكس، وتفتح السند الأصلي بصلاحية رؤية الحسابات. فتح المصدر يحتاج اتصالاً، والتقسيم غير المحفوظ يحتاج تأكيداً قبل إغلاقه. التصميم يستعمل نافذة ومكونات FINORA الحالية وشرح `?`.

## العقد المحاسبي

- الفاتورة تبقى أصل الدين؛ إنشاء الجدول لا يعيد تسجيل البيع أو القبض أو المخزون. السند الأصلي وتخصيصاته وإيصال القبض وسجل الفاتورة والقيود تبقى محفوظة.
- ينشأ سجل دفعات للأقساط بالمبالغ الموجبة والسالبة والتواريخ والموظف الأصلي من المصادر الموثقة. التحصيل المباشر يستعمل مرجع `IP`، والسندات مرجع `FV`؛ لا تؤخذ علامات السندات من ملاحظات خارجية.
- يحفظ جدول `customer_schedule_payment_link` ربطاً مستقلاً فريداً بين تخصيص الفاتورة الأصلي ودفعة الأقساط، مع دفعة العكس السابقة إن وجدت. يحظر حارس التطبيق تعديل الربط أو حذفه؛ لا تضاف تخصيصات بأثر رجعي إلى السند الأصلي.
- يعكس مسار الحسابات الحصة الأصلية نفسها بعد تغيير عدد الأقساط المستقبلية. السند الذي يجمع فاتورة ذات جدول سابق وفاتورة ذات جدول جديد يعكس حصصهما الأصلية معاً. يبقى صف التاريخ بهويته حتى إذا صار صافي التحصيل صفراً.
- السند المعكوس قبل الإنشاء يحفظ دفعة الأصل والعكس. صف الملخص قد يكون بقيمة ومدفوع صفرين؛ يحتسب ضمن حد 240 صفاً، ويقسم أصل الدين المتبقي فقط. تاريخ الملخص هو تاريخ الفاتورة، وليس استحقاقاً أو قبضاً جديداً.
- بعد عكس القبض بالكامل يعمل الترجيع والإلغاء: تحذف الأقساط الحالية، وتبقى دفعات المصادر بمبالغها وملاحظاتها وتواريخها وموظفيها، وروابطها الأصلية. يسمح الحارس فقط بفصل مراجع الخطة والقسط عند حذف خطة فاتورة ملغاة/مرتجعة بصافي صفر وبعد عكس جميع مصادر `FV`. الفصل من فاتورة نشطة أو تغيير البيانات المالية يبقى ممنوعاً. إذا كان السند المعكوس مشتركاً مع فاتورة أخرى مرتجعة، يتحقق تخصيص عكس حصتها المؤرشفة ولا يحظر جدولة الفاتورة النشطة بلا سبب.
- تعديل مواعيد المستقبل يقبل صف التاريخ الصفري الموجود والمرتبط بدفعات فقط، وبنفس تاريخ ومبلغ الصف المحمي. لا يمكن إنشاء قسط مستقبلي صفري بتعديل المبالغ؛ مجموع الأصل والمدفوع يبقى ثابتاً.

## الحماية

تطابق الشركة والفرع والعميل ونوع السند واعتماده وحالة العكس وحصة التخصيص ومبلغ السجل وحسابه ووسيلته يتحقق في السيرفر. السجل المفقود أو المكرر أو خارج النطاق يوقف الإنشاء دون آثار. القراءة لا تنشئ جداول أو ترقي schema قديمة. جدول الربط ينشأ عند أمر الكتابة فقط إذا كان مفقوداً.

بصمة المعاينة تشمل المصدر والسند والعكس والتخصيصات والدفعات؛ التغيير بعدها يعطي تعارضاً. أوامر الجدولة تبقى ذرية مع تدقيق السبب ومفتاح ثابت ومنع خطة ثانية للفـاتورة. ترتيب قفل سياسة الحسابات ثم الفاتورة يتبع أوامر الحسابات. فشل كتابة الرابط أو التدقيق يتراجع بالكامل، ويستطيع UUID نفسه إعادة المحاولة. لا ادعاء باختبار تزامن PostgreSQL فعلي لهذه الدفعة.
