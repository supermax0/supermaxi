# FINORA — تنفيذ الجرد والتحقيق الذكي

طلب المستخدم يقدم هذا العمل على بقية ERP. المرجع البصري يحدد سرعة العد والتفاصيل داخل الصفحة؛ ألوان ومكونات Desktop الحالية تبقى كما هي.

## الربط الذي ثبت بالفحص

- Flask / SQLAlchemy وقواعد الشركات المعزولة؛ Desktop React / TypeScript / Electron، وواجهات RTL الحالية.
- `BranchStock` هو رصيد مخزون الفروع؛ `ProductColorVariant` مصدر المتغيرات (اللون/المقاس/الحجم). نسخ الكتالوج المشتركة تحل بخدمات المخزون الحالية ولا تجمع نسخة المنتج مرتين.
- `StockMovement` و`InventoryQuantityAudit` و`InventoryStockSnapshot` مصادر الحركة والتغيير. أوقف مسار الجرد القديم `/inventory/save-audit` الذي كان يكتب الرصيد فوراً؛ صفحة الجرد القديمة تحوّل إلى المنظومة الجديدة، والـ POST القديم يرجع رفضاً واضحاً ولا ينشئ حركة نقدية.
- `WarehouseStock` و`WarehouseMovement` دفتر مستقل لوحدة الجملة. جلسة المخزن تستخدم هذا المصدر صراحة؛ لا تجمع دفتر الجملة مع مرآة مخزون الفروع وتعلن مجموعاً للشركة دون دليل تطابق الموقع.
- التحويلات والمبيعات والمشتريات والمرتجعات تستعمل مستنداتها الحالية. التحقيق قواعد مبنية على هذه الأدلة؛ تأخر الدفع وحده لا يثبت ضياع قطعة، وتطابق زيادة ونقص لا ينشئ تحويلاً تلقائياً.
- `JournalEntry` ودليل الحسابات وربط الحسابات والفترات وطبقات تكلفة `InventoryLot` تبقى المصادر المحاسبية؛ الجرد ليس قبضاً أو صرفاً نقدياً.
- جسر Offline مشفر موجود؛ العد المحلي يحتاج عمليات مستقلة مؤرخة مع تحقق حركات الخادم بعد المزامنة. الترحيل والاعتماد يحتاجان اتصالاً حياً.

## مراحل هذه المهمة

1. نماذج إضافية للجلسة وخطوطها وأحداثها مع مخطط آمن؛ نطاق ثابت وصلاحيات وعزل ومعرفات إعادة إرسال وإصدارات.
2. API للبحث والعد وإعادة العد والاستبعاد المسبب وسجل الجلسات؛ مقارنة on-hand وتذاكر بداية العد وكشف الحركات حتى عند رجوع الرصيد لنفس الرقم.
3. تحقيق موثق للمواقع والحركات والمستندات والتحويلات والعهد المتاحة، دون تعديل مخزون أو مستند أثناء القراءة.
4. مراجعة واعتماد وترحيل ذري للحركات والتكلفة والقيد، ومنع التكرار والتحويل الآلي والفترات المقفلة.
5. واجهة داخل المنتجات: الجرد وسجل الجرد، البحث والإضافة المستمرة والتعديل المباشر والتفاصيل والمراجعة والشرح والتقارير بنمط FINORA.
6. العد Offline واسترجاع الطلبات وتعارض المزامنة والمسح، بقدرات صريحة للكاميرا/الأرقام التسلسلية الفعلية.
7. اختبارات خدمة وقاعدة حقيقية وصلاحيات وحركة أثناء العد، ثم الأنواع والتنسيق والبناء والمسارات الكاملة وصور الهاتف والدسكتوب والطباعة.

الحالة: المنظومة منفذة في المشروع وبناء Desktop المحلي؛ مراجعة المسارات النهائية موثقة في `docs/finora-smart-inventory-audit-verification.md`. لم ينشر التغيير على سيرفر إنتاجي أو يعدّل بيانات الشركة المستخدمة.
