# FINORA — إرجاع الطلب ووصل شركة النقل

الحالة: نُشر التحديث وأعيد فتح تطبيق FINORA المستخدم وتحقق عرض الميزتين على بيانات حية. المقصود رقم وصل/بوليصة لكل طلب، بحسب تأكيد المستخدم، وليس كشف شركة نقل مجمعاً.

في قائمة الطلب وتفاصيله: «إرجاع الطلب» للطلب القابل للإرجاع، اختيار فرع الاستلام الفعلي، ثم مراجعة وتأكـيد منفصلان. الطلب بحالة «تم الطلب» يستخدم الإلغاء؛ المقفل والراجع والملغي لا يعرض لها إرجاع جديد. هذه عملية إرجاع كامل؛ الإرجاع الجزئي والاستبدال والضمان باقية ضمن الخطة. صلاحية الإرجاع مستقلة عن إدارة الطلبات، وتراجع الخدمة صلاحية الوصول للطلب قبل التغيير.

حقل «رقم وصل / بوليصة شركة النقل» له إضافة/تعديل مباشرة من التفاصيل والقائمة. الافتراضي وصل واحد للطلب حتى لو بيه عدة قطع؛ خيار وصل لكل قطعة محفوظ، والأرقام المتعددة القديمة لا تستبدل دون إظهار التنبيه. الإدخال اليدوي لا يحفظ تلقائياً مع Enter. حفظ الوصل للطلب الجديد أو المعبأ يحوله للشحن وفق السياسة الموجودة، ويظهر ذلك قبل الحفظ. الرقم ظاهر بالصف والتفاصيل والبحث والطباعة والسجل؛ البحث يشمل الوصل الثاني أيضاً. علامة `؟` تشرح الإرجاع والوصل وطريقة الأرقام.

الإرجاع يستخدم خدمة المخزون ودفعات FIFO الحالية، ويعكس التحصيل عن الحسابات الأصلية ويلغي خطط الدين/الأقساط حسب القواعد القائمة. كشف الفحص أن تحصيل شركة النقل كان يبقى بالصندوق بعد عكس دفتر الفاتورة: أضيفت حركات «عكس تسديد» سالبة مرتبطة بنفس الفاتورة والشركة والحساب والفرع، مع حفظ الأصل. الخزينة تعتبرها عكس قبض وتستبعد ازدواجها مع دفتر الفاتورة. لا يصلح التحديث فواتير راجعة قديمة تلقائياً، ولا يعيد ترحيل الجرد أو يمس القطع الست التي وصلت بعده. السند المالي المحمي يتطلب عكس أصله، ولا يتجاوزه مسار الإرجاع.

الواجهة تعرض عدد الطلبات التي أعيدت فعلاً، وتوضح الراجعة مسبقاً والفاشلة دون إعلان نجاح الجميع. تتحدث ذاكرة الطلبات والمخزون والعملاء والحسابات والتقارير ونقطة البيع بعد العملية.

الطباعة تستخدم القالب المختار. القالب الافتراضي يحتوي الشركة والرقم، وتضيف خدمة صغيرة تعتمد مكتبة Python القياسية الرقم داخل بطاقة الزبون أو داخل صفحة القالب المخصص عند غيابه. لا تعيد تنسيق بقية HTML، وتهرب النص الخارجي وتمنع التكرار. لا تحتاج حزمة جديدة على السيرفر.
