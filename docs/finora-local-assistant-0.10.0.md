# FINORA Desktop 0.10.0 — المساعد المحلي

المساعد موجود في جميع أقسام الدسكتوب، مع محادثة تستمر عند الانتقال بين الصفحات، وسياق القسم والسجل المفتوح. الاختصار `Ctrl+Shift+A`، وزر المساعد، وبطاقة الرئيسية تفتح نفس المحادثة. التعليم والبحث المباشر مستقلان عن جاهزية النموذج.

## التفعيل من الإعدادات

1. افتح **الإعدادات ← المساعد المحلي**.
2. اختر Ollama أو LM Studio. العنوان الافتراضي `127.0.0.1`؛ المنفذ `11434` لـ Ollama و`1234` لـ LM Studio.
3. نزّل نموذج Instruct محلياً داخل الخدمة. اختر نموذجاً يدعم العربية واستدعاء الأدوات، وحجماً يناسب ذاكرة الجهاز. الصور تحتاج نموذج رؤية وتفعيل خيار الصور في فينورا.
4. في Ollama شغّل الخدمة؛ أو في LM Studio حمّل النموذج وافتح Developer وشغّل Local Server. اضغط **فحص الاتصال وجلب النماذج** في فينورا واختر النموذج.
5. فعّل المساعد واحفظ. زر **اختبار استجابة النموذج المحفوظ** يختبر النموذج بدون إرسال بيانات مالية.
6. رمز الوصول اختياري إذا كانت الخدمة تطلبه؛ يخزن مشفّراً بواسطة Windows ولا يرجع للواجهة.

فحص Ollama:

```powershell
ollama list
ollama serve
```

الأمر الثاني مطلوب عند عدم تشغيل الخدمة؛ إذا كانت تعمل أصلاً فلا تشغّل نسخة ثانية على المنفذ نفسه. في LM Studio يمكن استخدام واجهة Developer أو `lms server start --port 1234`.

لجهاز قديم يمكن تشغيل النموذج على جهاز متوافق داخل الشبكة، وتفعيل الاستماع للشبكة في الخدمة، واستخدام عنوان IPv4 الداخلي لذلك الجهاز. البيانات والصور تذهب إلى الخدمة المحلية المحددة. عميل Windows 7/8 يبقى على Electron 22؛ توافق برنامج النموذج نفسه ومتطلبات ذاكرته مستقلان عن توافق عميل فينورا. لا ينزّل فينورا نماذج كبيرة تلقائياً.

## ما يستطيع المستخدم فعله

- **علّمني:** دليل مدمج لكل أقسام البرنامج الـ17، مع خطوات مفصلة للعمل الأساسي، وتحديد العنصر المقصود عندما يكون ظاهراً، وحفظ تقدم التعليم حسب الحساب والنطاق. التقدم إقرار المستخدم بمراجعة الخطوة، وليس إثبات تنفيذ معاملة.
- **بحث البيانات:** بحث العملاء والطلبات والمنتجات والموردين والمندوبين ضمن الأدوات المسموحة للحساب، حتى بدون تشغيل LLM.
- **المحادثة المحلية:** شرح البرنامج، تحليل النتائج، ملخص بداية الدوام، المقارنات والأسئلة المتتابعة حسب الأدوات المتاحة. النتائج تعرض مصدر القراءة ووقتها وفلاترها وروابط السجلات الأصلية.
- **مراجعة المقترحات:** حقول أساسية لمنتج أو عميل أو مصروف أو سند قبض، أو سطور بيع/شراء. تفتح في النماذج الأصلية للمراجعة؛ لا حفظ أو ترحيل أو حذف من المساعد. الأطراف والحسابات والدفع يحددها المستخدم هناك. أسعار الفاتورة الحالية تأتي من واجهات فينورا الأصلية، وهويات المنتجات تحتاج نتائج متحققاً منها وقراءة جديدة قبل تعبئة السطور.
- **شرح الصفحة / الخطأ:** يرفق اسم القسم والنص الظاهر من رسائل الخطأ فقط، ثم يطلب شرح السبب المؤكد وخطوات التحقق. لا يجمع حقول النماذج أو كلمات المرور.
- **صورة:** معاينة محلية، إزالة بيانات الصورة الأصلية بإعادة الترميز، وتصغيرها قبل إرسالها عند الضغط على إرسال. الصور لا تحفظ في سجل المحادثة.
- **صوت:** تسجيل بطلب المستخدم حتى دقيقة، تحويل إلى WAV أحادي 16 kHz، ثم تفريغ محلي إلى نص قابل للمراجعة قبل الإرسال.

## تفعيل الصوت الاختياري

شغّل `whisper.cpp` بنموذج متعدد اللغات، لا نموذج `.en`، ثم فعّل الصوت والمنفذ من إعدادات المساعد:

```powershell
whisper-server -m models/ggml-base.bin --host 127.0.0.1 --port 8080 -l ar
```

تستخدم الواجهة `/inference` مع ملف WAV و`response_format=json`. يلزم تثبيت الخدمة والنموذج بشكل مستقل؛ لا يوجد تحويل صوت عبر خدمة سحابية ولا إرسال تلقائي للنص كمعاملة.

## الصلاحيات والخصوصية

الاستدلال في Electron main عبر HTTP إلى loopback أو IPv4 خاص فقط؛ لا مفاتيح OpenAI ولا استدعاء سحابي بديل. المسارات ثابتة، والتحويلات HTTP لا تتبع، والاستجابة والوقت وعدد الجولات وحجم السياق محدودة. Ollama يُفحص قبل الاستدلال لمنع النماذج التي تعلن اتصالاً بعيداً، وتُرفض أسماء cloud. لا يستطيع هذا العميل ضمان إعدادات خادم خاص يديره طرف آخر؛ استخدم خدمة تثق بها.

السيرفر يوفر فقط `GET /finora-ai/api/desktop/tools` و`POST /finora-ai/api/desktop/tool`. يستعملان جلسة فينورا والصلاحيات ومفاتيح ميزات الشركة ومحركات القراءة الحالية وسجل التدقيق. رمز النطاق يمنع إعادة طلب أدوات بعد تغيير الحساب أو نطاق الفروع. معاملات هوية الشركة والمستخدم والصلاحيات داخل arguments مرفوضة. لا توجد أدوات كتابة مالية أو SQL عام.

حفظ المحادثة اختياري ومغلق افتراضياً. عند تفعيله تخزن آخر 40 رسالة نصية مشفرة بـ Windows safeStorage، ومعزولة حسب عنوان السيرفر والشركة والمستخدم والفرع والصلاحيات التي يثبتها السيرفر. تغيير النطاق يلغي الطلب ويمسح ذاكرة المحادثة الحالية والمسودة المعلقة. تحميل المحفوظ يحتاج جلسة موثقة؛ لا يوجد حفظ بنص مكشوف عند تعذر التشفير. السجلات المسترجعة موسومة كمحفوظة وتحتاج تحديث الأرقام.

الذكاء اللغوي قابل للخطأ. تعليمات النظام تطلب أداة حديثة للأرقام، وتمنع اختلاق نجاح أو اختيار طرف مبهم؛ الحفظ الفعلي يبقى في النماذج الأصلية. عرض المصدر والمراجعة جزء من طريقة الاستخدام، وليس ضماناً لدقة كل عبارة يولدها أي نموذج.

## التحقق والإصدار

أصلح الإصدار أيضاً مسح رقم الطلب أثناء الكتابة في نافذة تعديل الفاتورة عندما يعيد الأب تحديث الواجهة. إعادة الضبط مرتبطة بفتح النافذة فقط، واختبار التراجع يعيد تحديث الأب أثناء وجود الرقم ويتحقق من بقائه كاملاً. وأصبحت أولوية Escape تحافظ على النموذج المالي عند فتح المساعد أو الشرح.

تفاصيل التحقق الفعلية تحفظ في `.codex-tmp/assistant-release/validation.md` في بيئة الإصدار. تشمل بروتوكولي Ollama وLM Studio بخادم HTTP اختباري، الإلغاء، رفض المضيف العام والتحويلات، حدود الاستجابة، سجل المحادثة والتشفير، واجهات أدوات السيرفر، واختبارات واجهة Electron بأوضاع التطوير والنسخ المجمّعة.

لم تكن خدمات Ollama/LM Studio متاحة محلياً عند بدء العمل؛ اختبارات البروتوكول ليست تقييماً لجودة نموذج محمّل أو أداء جهاز المستخدم. يحتاج الاستخدام الفعلي تفعيل الخدمة والنموذج من الإعدادات. لم يتوفر جهاز Windows 7/8 فعلي، ولا شهادة توقيع Windows؛ تبقى هذه حدود التحقق والتوزيع.

مراجع التنفيذ الرسمية: [Ollama Chat](https://docs.ollama.com/api/chat)، [LM Studio Tools](https://lmstudio.ai/docs/developer/openai-compat/tools)، [whisper.cpp server](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/README.md).
