# تقرير ميزات وتطويرات Finora Phone

**تاريخ التقرير:** 5 آب 2026  
**الإصدار الحالي المنشور:** `1.0.11+12`  
**نطاق العمل:** Phase 1 (Companion CRM Overlay) + Phase 1.5 (Production Hardening) + تحسينات واجهة ونافذة عائمة  
**حالة Phase 1.5:** جاهز للاختبار الميداني (`READY FOR FIELD VALIDATION`) — لا يُعتبر مكتملاً نهائياً حتى اجتياز يوم عمل كامل على هاتف الشركة.

---

## 1. ملخص تنفيذي

تم بناء تطبيق **Finora Phone** كتطبيق مرافقة (Companion) لنظام Finora ERP على أندرويد.ش يبقى تطبيق الاتصال الأصلي مسؤولاً عن الرد والرفض، بينما يعرض Finora فوقه معلومات الزبون وأدوات CRM سريعة دون التدخل في Android Telecom.

التطبيق يعمل Offline-first مع مزامنة لاحقة، ويدعم تسجيل الدخول ببيانات موظفي Finora، ويظهر في إعدادات الشركة بجانب باقي تطبيقات Finora للتحميل.

---

## 2. المعمارية العامة

| الطبقة | التقنية |
|--------|---------|
| واجهة الموبايل | Flutter (Riverpod + GoRouter + Material 3) |
| طبقة أندرويد الأصلية | Kotlin — مراقبة المكالمات + Overlay Service |
| التخزين المحلي | SQLite + FlutterSecureStorage |
| الخلفية (Backend) | Flask API تحت `/api/phone/v1/*` |
| قاعدة البيانات | جداول Phone عبر migrations رسمية (بدون `db.create_all`) |

### مسار أحداث المكالمة (مسار إنشاء واحد)

```text
CallEventSource (Telephony | Receiver | CallLog | ActiveSession)
      ↓
CallEventCoordinator
      ↓
CallStateMachine   (call_status فقط)
      ↓
LocalCallRepository
```

- **Idempotency أساسي:** `device_uuid:local_call_uuid`
- **بصمة مصالحة ثانوية:** `phone|direction|bucket|device|sim`
- المعمارية جاهزة لاحقاً للانتقال إلى Full Default Dialer عبر `InCallService` دون إعادة بناء كاملة.

## 3. Phase 1 — الميزات الأساسية

### 3.1 المصادقة والأمان

- تسجيل دخول موظفي Finora عبر Bearer Token مربوط بالـ tenant.
- معالج صلاحيات داخل التطبيق (Phone State، Call Log، Overlay، Notifications، Contacts).
- قفل التطبيق بـ PIN / بصمة (App Lock) مع تجاوز آمن لشاشات أدوات المكالمة وبعد المكالمة.
- خيار حظر لقطات الشاشة (Secure Flag).
- ظهور التطبيق في **إعدادات الشركة → التحميلات** مثل باقي تطبيقات Finora.

### 3.2 واجهة الاتصال والزبائن

- لوحة اتصال حديثة (Dial Pad) مع الاتصال عبر Intent (`ACTION_DIAL` / `ACTION_CALL`).
- بحث فوري عن الزبون حسب رقم الهاتف (محلي ثم شبكة).
- تطبيع الأرقام العراقية بصيغ متعددة:
  - `077xxxxxxxx`
  - `96477xxxxxxxx`
  - `+96477xxxxxxxx`
  - أرقام تحتوي مسافات أو شرطات
- صفحات: الهاتف، سجل المكالمات، الزبائن، المهام، الإعدادات، لوحة معلومات، المفضلة/جهات الاتصال.
- بطاقة تفاصيل الزبون: الرصيد، الطلبات المفتوحة، آخر ملاحظة، VIP، القائمة السوداء، المشتريات.

### 3.3 النافذة العائمة (CRM Overlay) — الإصدار الأول

- تظهر أعلى الشاشة عند الرنين/الاتصال دون تغطية أزرار الرد/الرفض.
- عرض اسم الزبون والرقم والرصيد والطلبات وVIP/القائمة السوداء.
- قابلة للسحب ضمن أعلى ~28% من الشاشة، وقابلة للتصغير.
- الضغط يفتح أدوات المكالمة داخل التطبيق (إجراء آمن فقط — لا رد ولا رفض من الـ Overlay).
- إشعار بعد المكالمة لإكمال الملاحظة/المهمة حتى لو أُغلق التطبيق.

### 3.4 أدوات أثناء المكالمة

- حفظ ملاحظات مرتبطة بالمكالمة والزبون.
- إنشاء مهمة متابعة.
- إنشاء زبون سريع.
- بحث منتجات وإضافة كميات.
- مسودة طلب (لاحقاً استُبدلت بتأكيد مباشر — انظر القسم 6).

### 3.5 سجل المكالمات والمهام

- سجل مكالمات محلي مع مزامنة إلى Finora.
- حالات المكالمة: `detected → ringing/dialing → answered → ended` مع فروع `missed | rejected | failed | cancelled`.
- حالات المزامنة منفصلة: `pending | syncing | synced | failed | permanently_failed`.
- مكالمات فائتة → إنشاء مهمة متابعة تلقائياً حسب إعداد الدقائق من Bootstrap.
- صفحة مهام للمتابعة اليدوية والآلية.

### 3.6 العمل دون إنترنت

- تخزين محلي أولاً (SQLite).
- Outbox للملاحظات والمهام والطلبات والأحداث الفاشلة مع إعادة المحاولة.
- صفحة العناصر الفاشلة في الإعدادات للتشخيص.

## 4. Phase 1.5 — تقوية الإنتاج والاختبار الميداني

### 4.1 موثوقية أحداث المكالمة

- دمج مصادر الرقم على Android 12+ (حيث `TelephonyCallback` لا يعيد الرقم):
  - Broadcast `PHONE_STATE`
  - رقم الاتصال الصادر من `dialNumber`
  - استعادة من Call Log بعد انتهاء المكالمة
- فترة انتظار قصيرة (~450ms) قبل إرسال حدث البداية لإتاحة وصول الرقم.
- منع فتح Overlay مرتين عبر بوابة عملية مشتركة.
- Fallback محلي لجهات الاتصال إذا لم يستجب Flutter خلال ~4.5 ثانية (إيقاف التحميل اللانهائي).
- مصالحة مع Android Call Log عند إعادة فتح التطبيق بعد القتل.

### 4.2 Migrations الخلفية

- استبدال `db.create_all` بمهاجرات رسمية:
  - جدول `phone_app_devices`
  - أعمدة حالة المكالمة والطوابع الزمنية
  - `idempotency_key`، `device_id`، `sim_slot`، `local_call_uuid`
  - فهارس وقيود uniqueness
  - جداول/أعمدة الملاحظات والمهام ومسودات الطلبات
- أوامر CLI: `flask phone-db upgrade / upgrade-all / current / downgrade`
- اختبارات: تطبيع الأرقام، التصلّب (hardening)، المهاجرات والحالات.

### 4.3 التشخيص (Diagnostics) — Field Test فقط

- اختبار Sync / API / Overlay / Customer Lookup / إشعار محلي.
- تحذير Force Stop (أندرويد يوقف المكوّنات حتى يفتح المستخدم التطبيق يدوياً).
- تقرير يوم ميداني وتصدير التقرير.
- لا توجد بيانات وهمية (Mock) على مسارات المكالمة الإنتاجية.

### 4.4 ما هو خارج النطاق حالياً

| الميزة | الحالة | السبب |
|--------|--------|--------|
| تسجيل المكالمات (Recording) | Stub فقط | قيود أندرويد الحديثة (خصوصاً Samsung) تمنع تسجيل ثنائي الاتجاه بشكل موثوق من Companion Overlay |
| الذكاء الاصطناعي | Stub | مؤجّل لمرحلة لاحقة |
| قائمة الانتظار (Queue) | Stub | مؤجّل |
| التقارير المتقدمة | Stub | مؤجّل |

## 6. تحسينات أدوات المكالمة والطلبات

### 6.1 إنشاء زبون من Overlay / أدوات المكالمة

بدل زر «زبون سريع» البسيط، أصبح النموذج يشمل:

- الاسم
- الرقم (من المكالمة الحالية)
- العنوان
- قائمة المحافظات من إعدادات النظام عبر Bootstrap (`provinces` + `primary_province`)

### 6.2 تأكيد الطلب مباشرة (بدل المسودة فقط)

- تغيير مسار الطلب من «حفظ مسودة» إلى **تأكيد الطلب وإرساله إلى صفحة الطلبات**.
- على الـ Backend: إنشاء فاتورة فعلية مع `OrderItem` وخصم المخزون وحالة `تم الطلب`.
- على التطبيق: `createConfirmedOrder` → إنشاء ثم تأكيد فوري عبر API.
- إزالة الاعتماد على عرض «مسودة طلب» كمسار أساسي أثناء المكالمة.
- إصلاح الفراغ الأبيض فوق المحتوى عند فتح صفحة الأدوات كصفحة كاملة (`fullPage`).

## 7. إعادة تصميم النافذة العائمة وإضافة ميزات (v1.0.11+12)

### 7.1 التصميم الجديد

- بطاقة داكنة بحواف دائرية وإطار ذهبي.
- أفاتار دائري يعرض أول حرف من اسم الزبون.
- اسم الزبون بخط عريض + الرقم أسفله.
- مؤشر تحميل يختفي فور وصول بيانات CRM.
- شرائح (Chips) بدل سطر نص واحد:
  - الرصيد (بتنسيق آلاف)
  - الطلبات المفتوحة
  - إجمالي المشتريات
  - VIP
  - القائمة السوداء
- شريط تحذير أحمر واضح للزبون في القائمة السوداء.
- زر تصغير + زر إخفاء (X).

### 7.2 الميزات الجديدة للنافذة

| الميزة | السلوك |
|--------|--------|
| مؤقّت المكالمة | يبدأ لحظة الرد (`ACTION_ANSWERED`) ويعرض `MM:SS` |
| أدوات | يفتح صفحة أدوات المكالمة |
| ملاحظة | يفتح الأدوات ويركّز حقل الملاحظة مباشرة (`/tools?focus=note`) |
| مهمة | يفتح الأدوات وينشئ مهمة متابعة فوراً (`/tools?focus=task`) |
| واتساب | يفتح محادثة WhatsApp مع تحويل `07xx` → `9647xx` |
| نسخ الرقم | ضغطة مطوّلة على الرقم |
| إخفاء لهذه المكالمة | زر X — لا تعود النافذة لنفس الرقم حتى تنتهي المكالمة |
| تصغير محسّن | شريط مضغوط؛ الضغط يعيد التوسيع |

### 7.3 قواعد السلامة المحفوظة

- لا يوجد زر رد أو رفض داخل النافذة.
- لا تأكيد طلب من داخل الـ Overlay نفسه.
- النافذة تبقى في أعلى الشاشة ضمن أول ~28%.
- أزرار الإجراءات السريعة تظهر **بعد الرد فقط** حتى لا تزاحم واجهة الرنين.

## 11.1 جلسة تعمل بدون اتصال (`1.0.13+14`)

قبل هذا الإصدار كان التطبيق يستدعي `/auth/me` عند كل فتح، وأي فشل — بما فيه انقطاع
الإنترنت — يعيد الحالة إلى «غير مسجّل» ويُظهر شاشة الدخول رغم أن التوكن محفوظ.

| التغيير | الملف |
|---------|-------|
| حفظ جلسة الموظف مشفّرة لفتح التطبيق بدون شبكة | `lib/core/storage/token_storage.dart` |
| الخروج فقط عند رفض الهوية (401/403 أو `token_invalid`/`device_revoked`) | `lib/features/auth/data/auth_controller.dart` |
| اعتبار أي استجابة غائبة انقطاعاً لا فشل مصادقة | `lib/core/api/api_client.dart` |
| تجديد التوكن يستخدم `tenant_slug` المحفوظ بدل الثابت | `lib/core/api/api_client.dart` |
| إعادة التحقق تلقائياً عند عودة الاتصال | `lib/features/overlay/data/active_call_controller.dart` |
| شريط «وضع بدون اتصال» مع إعادة محاولة | `lib/app/shell.dart` |
| مزامنة تغيير حالة مهمة أُنشئت بدون اتصال | `lib/core/sync/sync_engine.dart`، `lib/data/repositories/repositories.dart` |

الاختبارات: `test/auth_offline_session_test.dart`.

## 11.3 تسجيل المكالمات من مسجّل النظام (`1.0.15+16`)

هواتف الشركة (Xiaomi) تسجّل المكالمات عبر تطبيق الاتصال الأصلي. بدل محاولة
التسجيل داخل التطبيق (مقيّد بأندرويد)، يلتقط Finora التسجيل الجاهز من مجلد
مسجّل النظام بعد نهاية كل مكالمة مُجابة، يطابقه مع المكالمة (بالوقت والرقم)،
ويرفعه تلقائياً عبر الـ outbox — يعمل حتى مع انقطاع النت وقت المكالمة.

| الجزء | التفاصيل |
|-------|----------|
| العثور على التسجيل | `CallRecordingFinder.kt` — بحث MediaStore بمجلدات MIUI/HyperOS ومطابقة بالرقم والوقت |
| صلاحية ملفات الصوت | `READ_MEDIA_AUDIO` (أندرويد 13+) — خطوة جديدة بمعالج الأذونات |
| الالتقاط والرفع | `RecordingRepositoryImpl` + عملية `upload_recording` بالـ outbox (multipart) |
| الباك اند | Migration v4: أعمدة `recording_*` على `phone_call_log` + `POST/GET /calls/<id>/recording` |
| التشغيل | زر تشغيل بمخطط الزبون الزمني (`recording_player.dart` عبر `MediaPlayer` الأصلي) |
| التفعيل | علم `recording` عبر `PHONE_FF_RECORDING=true` بالسيرفر |

التسجيلات تُخزّن خارج `static/` وتُبث فقط عبر رابط مُصادق عليه.
الاختبارات: `modules/phone_app/tests/test_recordings.py`.

## 11.4 إصلاح انهيار الإقلاع (`1.0.16+17`)

الإصدار `1.0.15+16` كان ينهار لحظة الفتح على أندرويد 14+. السبب: مكتبة الصوت
`just_audio` تجرّ `audio_session 0.1.21` التي تسجّل مستقبل بث بدون تحديد
`RECEIVER_EXPORTED`/`RECEIVER_NOT_EXPORTED` — وهو ممنوع لأي تطبيق يستهدف
أندرويد 14، فيرمي النظام `SecurityException` ويقتل التطبيق عند تسجيل الإضافات.

الحل: حذف المكتبة الخارجية كلياً وتشغيل التسجيلات عبر `android.media.MediaPlayer`
داخل إضافة Finora الأصلية (`playerOpen` / `playerPlay` / `playerSeek` /
`playerState` / `playerStop`) — لا مكتبات صوت خارجية، وحجم APK أصغر بـ 0.5MB.

الدرس: أي مكتبة أصلية جديدة تُسجّل نفسها عند إقلاع المحرك، فأي استثناء داخلها
يقتل التطبيق قبل ظهور أي شاشة. تُفضّل القناة الأصلية المملوكة للمشروع عند
الحاجة لوظيفة صغيرة.
